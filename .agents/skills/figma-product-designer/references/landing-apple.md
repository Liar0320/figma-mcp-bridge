# Landing / Apple-inspired

这是 `figma-product-designer` 的一种设计模式，不是独立 skill。用于明确要求苹果官网气质的公开 Landing Page、产品发布页或产品展示页。不是 iOS 界面模板，也不用于 Shopify Admin 等已登录任务页面。

## 来源与采用边界

2026-10-03 检索并读取：

1. 社区 skill `emilkowalski/skills/apple-design`：https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md
   - 已阅读源码。采用其克制、文字层级、即时反馈、空间一致性、减少动态效果原则。
   - 它主要讨论交互与动效，不是完整 Landing 模板，也不是 Apple 官方规范。不要照抄弹簧参数、强制玻璃材质、初始回复或工具安装行为。
2. Apple MacBook Air 产品页：https://www.apple.com/macbook-air/
   - 已读取页面结构与 Hero 产品图。观察到产品名称、短利益标题、清晰购买入口、主视觉、亮点、按主题深入解释，以及具体主张的证据/脚注。
   - 学习叙事和产品聚焦，不复制 Apple 商标、产品图片、口号、认证或销售数字。
3. Apple Motion 指南：https://developer.apple.com/design/human-interface-guidelines/motion
   - 本次静态读取只能获取官方摘要，不能据此声称已核实全文或营销站动效参数。涉及实现时再读取完整官方指导。

其他搜索结果只作为发现线索。不要把“白底 + 大字 + 蓝按钮 + 毛玻璃”当成该模式的充分条件。本模式下的尺寸范围是实践起点，不是从 Apple 页面测得的精确 token。

## 1. 先定叙事，不先选特效

为每一屏写出一个用户问题及回答它的证据：

| 叙事任务 | 内容与表现 |
|---|---|
| 我为什么关心 | 一句具体价值标题，交代产品类别与受众；不写空泛的“重新定义未来” |
| 它到底是什么 | 一个占主导的产品主视觉：实际产品图、授权截图，或原生可编辑的机制示意 |
| 为什么可信 | 功能如何兑现承诺、边界条件、可验证证据；没有客户数据就不造社会证明 |
| 它适合我吗 | 使用流程、适用范围、权限/隐私或已确认价格；按产品选择，而非机械全加 |
| 下一步是什么 | 单一转化目标；页首/末尾可重复同一动作，不增加无关销售或邮箱表单 |

推荐起点：精简导航 → Hero → 关键产品证据 → 两至三个有主次的功能故事 → 信任边界/FAQ → 最终 CTA 与真实页脚。brief 要求优先，非固定栏目数；没有内容依据的区块删除。

保护性承诺若决定产品信任，应在 Hero 或紧随其后的证据区可见，不移到页尾小字。

## 2. 构图与节奏

- 每个段落只有一个视觉主角。标题与主视觉形成关系，不是标题下排列一整屏等权白卡片。
- Hero 可居中，也可偏轴；取决于产品图/示意。首屏必须同时让人理解产品和下一步，不能只有大口号。
- 以留白、字号对比、整幅产品展示和局部细节建立节奏。避免连续多个同尺寸卡片网格。
- 可用浅/深大区块切换叙事，但每次切换需有主题理由；每个背景独立检查对比度。
- 少量柔和阴影服务产品或浮层的层级。不要用大面积模糊、发光球、彩虹渐变掩盖缺失素材。
- Bento 只在真实功能具有主次分组时使用，不默认把所有信息装进 Bento。

## 3. 排版、颜色与尺寸起点

以下随品牌、语言与实际字体测量调整：

| 项目 | 桌面起点 | 窄屏起点 |
|---|---|---|
| 验证画板 | 1440 px；内容最大宽约 1120–1200 px | 390 px，并实际压测到 320 px |
| Hero 标题 | 64–88 px，约 1.05–1.15 行高 | 36–48 px，约 1.15–1.25 行高 |
| Section 标题 | 40–56 px | 28–36 px |
| 导语 | 20–24 px | 17–20 px |
| 正文 | 16–18 px，约 1.5–1.7 行高 | 16–18 px，保持可读，不整体缩放页面 |
| 水平边距 | 随最大内容宽度居中 | 20–24 px；更窄时可到 16 px |
| 章节留白 | 96–160 px，按叙事强弱变化 | 56–88 px，不照搬桌面巨大空隙 |

- 中文标题优先自然短句、合适字重和断行；不要盲目套英文负字距或过紧行高。
- 使用合法可用的字体并预检：Figma 可选已安装的 PingFang SC 配合 Inter 等；Web 系统字体栈只是实现建议。不要要求下载、嵌入或再分发 SF 字体。
- 可从暖度克制的中性色起步：白 `#FFFFFF`、浅灰 `#F5F5F7`、近黑 `#1D1D1F`、次文本 `#515154`。单一强调色例如蓝 `#0066CC`，但品牌色优先。
- 上述是候选颜色，不是官方 Apple token。验证每个实际文字/背景组合，不能认为浅灰文字天然可访问。
- CTA 以清晰标签、足够对比和至少 44 px 触达表达。圆角/胶囊不是必须；不是所有容器都要大圆角。

## 4. 产品视觉与素材缺失

优先级：用户提供且可用的真实素材 → 获准的产品截图 → 从已确认机制绘制的原生示意。

SaaS 没有硬件图片时可以让“核心行为”成为主视觉，例如唯一允许的数据变化及其保护边界。图中标注“机制示意”而不伪装为实时结果；辅助测试声明放在独立注释区。

没有真实素材时必须选择可诚实完成的构图，而不是留下空图片占位、伪造完整产品截图或借 Apple 设备替自己的产品背书。图像本身可以是图片，但标题、按钮和 UI 不可整页烘焙成贴图。

## 5. Figma 与响应式

- 页面纵向 Auto Layout；章节 Hug 高度；内容区以 Fill 与最大宽度组织；正文固定可用宽度并自动增高。
- 复用真实重复的 CTA、FAQ 行、导航项；遵从组件创建 skill，不构建无关组件库。
- 产品示意可在自己的 Frame 内局部叠放，但在页面正文流中占有明确空间；不要叠压 CTA 或规则说明。
- 窄屏重新编排而不是等比例缩小。左右布局改上下，图形适配容器，关键标签不能缩成不可读小字。
- FAQ 展开通过内容增高推动后续区块；桌面与窄屏都测试。页脚链接不足时明确待配置，不补假链接。
- 导航精简；若绘制移动菜单，交付展开态与返回/关闭规则。无需菜单时只保留品牌与必要行动，避免制作无功能菜单图标。
- CTA 地址没有配置时使用明确不可用状态及原因；有地址的视觉状态可作为独立条件样例，不能伪造真实链接来演示。

## 6. 动效是一种解释，不是入场券

- 默认先保证静态页面可理解；没有交互实现任务时只交付必要状态或动效注释，不宣称已实现滚动效果。
- 揭示动画仅帮助阅读顺序或解释变化，不能把内容隐藏到必须滚动触发才出现。
- 不劫持滚动，不强制全屏逐页滚动，不用大面积持续移动背景。
- 若提出动效，同时给出 reduced-motion 的静态或轻淡入方案；减弱透明度时保持对比。
- 按下给予即时视觉反馈，动作通常在释放时提交；可逆操作不锁死输入。不得把“按下反馈”误写成指针按下就执行购买/提交。

## 7. 模式验收

- Hero 能回答产品是什么、为谁、带来什么具体改变、下一步是什么。
- 主视觉说明产品，不是与业务无关的装饰；关键主张有依据。
- 同一转化目标贯穿页面，缺少真实链接时不显示虚假可用入口。
- 页面不是换成大字号的后台卡片墙，也不是 Apple 官方页面的复制品。
- 实际执行标题变长、容器 390→320、FAQ 展开和 CTA 内容变化，观察 Auto Layout；独立移动稿不是压力测试替代品。
- 静态、窄屏与可选 reduced-motion 方案都保留关键内容。
- 输出桌面/窄屏截图、节点 ID、素材来源与已验证范围；不承诺代码行为。
