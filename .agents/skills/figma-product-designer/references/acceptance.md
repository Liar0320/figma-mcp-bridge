# 设计验收与交接

用于代表页试样和最终交付。只报告实际观察或执行过的验证，不把此清单勾选等同于测试证据。

先按主 skill 选择模式。应用任务使用下列应用状态项；Landing 不强制制造授权、任务、表单或空列表来满足清单。没有该交互时记录“不适用及理由”，不称为已测试通过。Apple-inspired Landing 还需执行 [landing-apple.md](landing-apple.md) 的模式验收。

## 语义门槛

- [ ] 每页首要任务、主要操作和下一步清晰。
- [ ] 没有添加未经要求的业务能力、保证、数据或假链接。
- [ ] 连接成功、提交成功、处理中、任务完成和结果成功明确区分。
- [ ] 空、未知、加载中的数值不伪装成确定的 0。
- [ ] 错误说明发生了什么、是否改变数据以及可执行的恢复方式。
- [ ] 关键保护规则可发现；次要技术信息不抢占主任务。
- [ ] 示例内容和实现边界明确，但设计注释与产品 UI 分离。

## 视觉门槛

- [ ] 首屏有明确视觉重心；不把所有内容做成等权卡片。
- [ ] 标题、正文、辅助说明与操作有清楚层级。
- [ ] 状态色语义一致，不只依赖颜色；关键文字对比度已检查。
- [ ] 文案不过度重复，留白与密度适合任务。
- [ ] 实际截图无裁切、非预期重叠、过小字体和无意义图表。
- [ ] 应用的最高风险错误在整页上下文中呈现；Landing 的最高风险转化限制（例如安装地址缺失）在实际 CTA 区域可发现。

## 结构压力验证

使用临时副本或可恢复修改，保留验证前后证据，完成后清理自己的测试节点。

| 场景 | 实际操作 | 通过条件 |
|---|---|---|
| 长标题 | 换成约两倍长度的合理标题 | 自然换行，后续内容让位 |
| 长错误 | 增加多行、带长标识的原因 | 容器增高，操作不被遮挡 |
| 窄容器 | 调整实际内容容器到目标窄宽 | 正常内容流重排，关键操作无横向滚动 |
| 组件修改 | 修改实例文本或状态属性 | 其他元素跟随布局，无需逐节点移位 |
| 空与加载 | 切换相关设计状态 | 不假造数据，主要行动仍明确 |
| 不可执行 | 切换缺权限或提交中状态 | 禁用原因可见，恢复路径明确 |
| Landing Hero | 使用更长的真实价值标题 | 不裁切、不与主视觉重叠，CTA 仍可发现 |
| Landing 窄屏 | 实际将内容容器从 390 调到 320 px | 文本增高、视觉重排，不靠缩小整个页面 |
| Landing FAQ | 展开最长答案 | 后续区块自然下移，问答可完整阅读 |
| Landing CTA | 切换配置可用与地址缺失条件 | 标签和说明一致，没有伪造链接或无关主行动 |

布局诊断通过不能替代截图检查；两张独立宽窄截图不能证明 Auto Layout 正确。若工具无法执行某项，明确未验证，不声称通过。

## 交互规范交接

静态设计应说明但不得假称已实现：
- 输入标签、必填校验、错误位置、保留输入及提交锁定。
- 键盘顺序、焦点样式、模态框焦点约束和关闭后的焦点恢复。
- 返回/取消行为、筛选上下文、请求失败与加载恢复。
- Banner、Toast、Modal 的位置、优先级和不遮挡关键操作的规则。
- 长文本、表格折叠、字段堆叠及滚动规则。
- 未确认的时区、轮询策略、重试语义等明确列入交接边界，不替产品做无依据承诺。

## 完成交付格式

1. 位置：容器名称、节点 ID、有效链接（可获取时）。
2. 内容：页面、关键状态、响应式范围、组件和规范。
3. 证据：实际截图、做过的尺寸/内容压力验证、已修复问题。
4. 边界：静态设计或交互原型；未实现业务、未验证行为、未配置真实链接。

不因主页面已画好而丢掉已承诺的状态；也不为凑齐清单增加产品不需要的页面。以用户范围和真实验收为准。
